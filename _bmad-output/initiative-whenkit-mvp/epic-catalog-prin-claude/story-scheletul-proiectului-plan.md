## Intent

**Problem:** The repo has no code yet; every later ticket needs a working Electron + React + TypeScript project, a test runner, a linter that enforces the hexagon's boundaries, and a `whenkit` CLI command reachable from any terminal.

**Approach:** Generate the official Forge 8 Vite + TypeScript template outside the repo, bring its files in, reshape them into the spine's folder layout, add React, Vitest, the boundary lint rules and a separately built ESM CLI exposed through `npm link`.

## Boundaries & Constraints

**Always:** Pin exact versions from the spine's Stack (Electron 44.7.1, React 19.3.0, @vitejs/plugin-react 6.1.2, Vitest 5.0.4; TypeScript and Vite as resolved by the template). Code and comments in English. The window is started only through `npm start` (the VS Code terminal has `ELECTRON_RUN_AS_NODE=1`, which `electron-forge start` clears). Keep the template's fuses as they are. Window `webPreferences` set explicitly: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`.

**Decisions (author, 2026-10-13):** keep the plan whole despite ~1950 tokens; linter = oxlint from the template (AD-2 wording updated); license = MIT.

**Never:** No domain logic, SQLite, Zod schemas or `whenkit init`/`import` (tickets 2–3). No nested `.git` from the generator. No deb/rpm/zip makers (Windows only). No push.

## Design Notes

The CLI is built by its own Vite config, not by the Forge plugin, so `core` code resolves the same way in both bundles (`moduleResolution: bundler`). Output is a single `.mjs`, so it is ESM regardless of `package.json` `type`. The linked `whenkit` never loads `.env` (it targets the real workspace once code is on `main`); `npm run cli:dev` is the dev entry that loads `.env`.
